# 未公开旧原型的数据退出说明

适用范围：从未公开分发的旧 Axoterm/Axterm 原型转到首次公开的 Axterm 版本。依照 [ADR-023](../adr/ADR-023-clean-local-source-root-and-data-profile.md)，新版本使用独立的 `data-v2/` 与 `vault-v2/`；不会原位打开或升级旧数据库/Vault。只支持手动迁移与 Axterm 自有配置快照。

## 操作前

1. 完全退出旧原型。将其整个用户数据目录（包括数据库、`vault/`、设置和附件）复制到受控位置，核对副本可读取；保留原目录，不把它指向新版本作试验。密码和密钥只留在本机安全备份中，不通过工单、截图或 JSON 发送。
2. 若使用过旧远端同步，单独保留远端原对象/版本；当前 Axterm 不会读取或覆盖旧格式，**也不会自动转换旧资料**。
3. 在旧原型中记录需要保留的连接参数、分组、书签、命令、用户自建主题的可见设置和背景图来源。不要把旧便携 JSON 中缺失的自建主题或 Vault 密码误判为已备份。

## 迁入当前版本

- 对旧用户数据先做冷备份，然后让新版本以独立空白数据目录启动。不要将旧 `data/axterm.sqlite` 复制到 `data-v2/`，也不要把旧 `vault/` 复制到 `vault-v2/`；新数据库会在迁移前只读拒绝不受支持的格式。
- **不要**把旧便携 JSON 或单独主题文件交给“导入 Axterm 配置”。在当前版本手动重建主机/分组、书签、连接配置、命令与自建主题；只在当前应用的凭据界面重新输入密码，并重新选择背景图片。重建后导出新的 Axterm 配置快照作为以后迁移用的非密钥备份。
- 只有 `format: "axterm-configuration"` 的 Axterm 自有快照才适用“检查 / 导入 Axterm 配置”的预览与提交；导入前检查预览的新增项和冲突。它不会替用户恢复已省略的 secret 或图片。

逐项核对连接目标、Host Key、代理、书签、命令、自建主题和密码可用性，再停止使用旧原型。不要为“清理”而删除旧数据库、Vault 冷备份或远端旧对象；需要销毁时另按用户自己的保留政策处理。

## 已验证与未覆盖

旧候选的原位升级测试属于受控历史证据，不适用于 ADR-023 后的新数据目录。新候选必须验证旧数据库字节未改、旧 Vault 未读写、空白新目录可启动和 Axterm 自有配置可导入；测试结果见 [STATUS](STATUS.md) 最新记录。Windows/Linux 原生验证、发行负责人签收和未知个人数据差异仍开放。
