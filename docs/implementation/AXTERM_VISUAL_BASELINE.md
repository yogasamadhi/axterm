## 2026-09-23 rendered accessibility scan

The accessibility E2E injects test-only `axe-core@4.13.0` through the
Playwright Electron context before the renderer loads, preserving the
production Content Security Policy. It audits the rendered startup shell,
Settings common/legal/sync workspaces (both collapsed and expanded legal
documents), Host Manager with imported records, Add SSH dialog, Add RDP dialog,
terminal-theme workspace, Widgets, actual Legacy Prototype-data import preview and
success/failure states, and the independent Axterm configuration preview for
WCAG 2.0 A/AA, WCAG 2.1 A/AA, WCAG 2.2 AA and axe best-practice
violations. Existing
custom accessible-name, tab-order,
duplicate-ID, keyboard/focus-restoration and reduced-motion assertions remain
in place.

The rendered pass found issues static token tests could not expose:
host-group filters were declared as tabs despite containing ordinary filter
buttons; hint, metric and primary-button text had insufficient contrast;
heading levels skipped a level; Widget options used listbox semantics without
the required owned children during loading; Theme and Widget subviews nested a
second `main` landmark inside the Shell's main; and those subviews lacked a
visible page-level H1 while loading. These are corrected with named toggle
groups and `aria-pressed`, semantic text colors, correct heading hierarchy,
button-group semantics plus `aria-busy`, non-main content containers and
Axterm-owned visible page headings. Expanding Axterm's own license and
third-party notices also exposed scrollable `<pre>` elements missing from the
keyboard order; these now accept focus after their disclosure summary and show
a visible focus ring. The Legal page's subheadings and the updater status now
follow the page's h1→h2 hierarchy. Both accessibility journeys now pass, as do
all nine visual journeys in the full `bun run check`.

The first axe run against an actual imported Legacy Prototype-data preview found that
the mapping cards had `role="row"` without table cells, and were inside an
incomplete table structure. The report is a bounded collection of independent
cards rather than a true tabular dataset, so it now uses a named native list
with list items. Its create/unchanged/skip filters also expose their current
toggle selection through `aria-pressed`. The accessibility journey selects
the legacy JSON fixture through the native File Grant path, audits the real
preview, exercises the filter by keyboard, and cancels without importing. The
focused accessibility project passes both journeys with this added state. A
second native File Grant selection intentionally supplies malformed JSON; the
resulting import error and the non-committable independent-configuration
preview both use `role="alert"` so assistive technology receives the failure
without relying on color or visual placement. The E2E also exports and opens an
Axterm configuration snapshot, checks its Vault-preservation note, audits the
preview, then dismisses it with the keyboard. Both migration commit and retry
states pass axe.

After the synthetic import commits, the same E2E now audits Host Manager with
its imported rows rather than relying only on the empty startup state. This
found 3.95:1 contrast on the 9 px connection-state text; the style now uses the
Axterm semantic muted-text token. The contrast adjustment changes only the
populated Host Manager state, which has no checked-in screenshot baseline; it
is covered by the rendered axe journey.

The accessibility-driven switch from disabled/faint copy to the semantic
text-muted color intentionally changes rendered pixels. The four language
captures were inspected after the change; only the English capture crossed
the 1% image tolerance and was refreshed. Japanese, Simplified Chinese and
