## How to use this matrix

This is the execution ledger for desktop parity. Rows describe observable user
behavior, not source modules. A row stays **Partial** when Axterm has the main
API but lacks any reference menu, state, setting, shortcut, visual treatment or
packaged evidence. **Implemented** means code and automated behavior exist but
review evidence is incomplete. **Blocked** requires a matching `STATUS.md` Blocker
Register entry and does not count as parity. Only **Certified** and approved
**Not applicable** rows count toward the measured implementation coverage.

Every implementation change must update the row with links to Axterm source,
tests, screenshot evidence and platform results. If deeper comparison reveals a
new behavior, add a row; do not hide it inside an existing broad row. Upstream
paths below are relative to `vendor/electerm` and resolve at the pinned commit.

The normal target is 122/122. The accepted implementation delivery threshold is

applicable and at most one row may remain Blocked. A blocker records the exact task,
objective cause, last evidence, completed portion, unblock condition and resume point;
unfinished or difficult work remains Missing/Partial/Implemented. Missing mandatory
release evidence keeps Phase 10/21/Desktop 1.0 open even after the 99% implementation
threshold is reached.
