# Pi 源码引擎集成验收

Updated: 2026-10-05
Status: 本轮产品接入、源码快照、Mac 目录包及最终全仓门禁通过。

## 输入与范围

所有者要求以 Pi 作为 AI 助手引擎，并采用 Pi 的模型厂商配置方式，允许直接使用源码。
决策见 [ADR-027](../../../adr/ADR-027-pi-ai-source-engine.md)，操作说明见
[PI_AI_ENGINE](../../PI_AI_ENGINE.md)。本轮没有创建 Git 提交；保留原有工作区修改。

- 子模块：`vendor/pi`，`https://github.com/earendil-works/pi.git`。
- 固定提交：`5b6c792b424e73edefbfa558b901bcd64788dad2`，Pi 1.0.3，MIT / Mario Zechner。
- 目录：上游 Nix pin `sha256-c5d5070c7592ca8e27743e892a7eec1d6c883be8034f888735238cdfdb3ab70f`。
- 目录接口包含 42 个厂商、1,331 个支持 API 的模型；38 个厂商支持本轮 API Key 接入。
- 七种 API、内置模型、自定义 models/modelOverrides、Vault API Key 和 provider headers。
- OAuth/订阅登录、环境/命令凭据表达式、模型级 headers、嵌套 compat 与额外采样设置未接入。

引擎使用 Pi 的 AI 协议与 Agent loop，上游工作树的已跟踪文件未修改。
构建校验源码与目录哈希，离线生成忽略的模型数据；SDK 从冻结锁文件编入 Runtime。
只有私有引擎包可导入三个 Pi 源码树，只有 Runtime AI Adapter 可消费引擎包。
没有新增业务 IPC、Renderer SDK 调用、Extension Host 或自主工具执行。

electron-builder 26.16.1 沿用既有 ADR 例外。`package-desktop.mjs --dir --output`

finally 恢复 workspace 原生 Node ABI 构建。
