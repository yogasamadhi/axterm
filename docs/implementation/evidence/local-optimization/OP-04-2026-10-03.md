## 修改与行为

- Transfer Contract 增加可选 `retryAvailability`，由当前 Runtime generation 推导。
  失败或取消且请求、连接均有效时才允许重试；请求已过期与连接不可用分别显示重新
  选择文件或重新连接提示。旧记录缺少该字段时不猜测可重试；UI 提交失败可见，并用
  同步保护避免重复分发。该能力不持久化到业务 DB，重启不恢复旧 Grant 或内存请求。
- 活动传输上限保持 32，已结束的重试请求最多保留 200；成功、清除历史和 shutdown
  释放请求。一次重试消费原请求，重新校验 File Grant。列表显示已授权的真实目标
  路径，不把 Grant ID 当作本地文件名；SQLite 更新保留实际路径。
- 覆盖已有远端文件先等待明确冲突决策，再使用 SFTP atomic replace。服务器不支持
  时返回 `TRANSFER_ATOMIC_REPLACE_UNAVAILABLE`，保留原文件并清理 `.part`；没有
  删除原文件的降级覆盖。UI 给出改名或跳过的恢复说明。
- SSH 断开会结束暂停或冲突等待并标记失败；用户取消仍为 canceled。工作池在首个
  错误后停止领取新任务，等待已持有的 stream 收尾再关闭 SFTP。shutdown 先解除
  暂停等待，再等待全部任务；重启恢复包含 paused 和 awaiting-decision 状态。
- Widget SFTP 增加 channel end 确认，修复关闭通道未完成、后续远端列表挂起的问题。
  Widget stop 等待 server close 回调；shell 的输入监听与 PTY 订阅确定性释放。
  SSH2 SFTP close 跟踪公开 end/close 事件，处理已经结束的 channel；重复或并发调用
  共用同一关闭 Promise，不依赖类型声明未公开的 readable 属性。
- 传输中心组件与 Client action hook 移入静态 `app/transfers/` 模块，Shell 显式组合。
  这是 OP-06 的局部基础，不代表 OP-06 已完成。
- 五项恢复文案覆盖简体、繁体、英语、日语；当前核心文案范围每语言 2,547 项。
  人工语言和来源权利签收继续保持 pending，不以生成台账代替签收。

G-11 使用 192 KiB 含全部字节值的 binary payload，读取实际本地与远端文件逐字节
比较；递归与多选同样核对实际文件。取消和不支持 atomic replace 的覆盖均确认原
文件未改变、临时文件已清理；Runtime 重启后历史不可重试，文件区要求重新授权。
重试提交错误提示使用一次 HTTP 503 注入，只证明 UI 错误展示；随后恢复真实路由
验证真实冲突决策。该注入不作为协议或传输成功证据。

OpenSSH Runtime 旅程保留既有 256 MiB streaming，并增加 binary 上传、已批准的
atomic replace 和下载逐字节比较；桌面 B-12 保留 128 MiB 暂停、继续、取消、临时
文件清理及真实右键/多选下载。Widget 不支持 atomic replace 的失败语义与 OpenSSH
支持该能力的成功语义分别验证，不把二者混为同一种服务器能力。

PTY 订阅所有权两项回归使用真实 SSH 网络与注入的 PTY factory，证明监听和关闭
