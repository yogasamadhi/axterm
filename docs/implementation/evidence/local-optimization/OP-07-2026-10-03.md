## 实现与业务边界

按 [ADR-025](../../../adr/ADR-025-ai-context-review-receipt.md) 实施。
新增经过 Runtime 鉴权的 `POST /api/v1/ai/context-preview`，Contract/Client/OpenAPI
共用同一结构，独立 HTTP feature 只调用 Application Service。预览本身不创建 run、
tool、conversation 或持久化 receipt，不调用 Model Provider。没有新增业务 IPC、
Plugin Kernel、Extension Host 或依赖；Runtime 保留 Node/utilityProcess 边界。

Runtime 的预览与发送使用同一 builder，返回实际系统指令、问题、上下文和来源。
历史查询只读取最近 32 条并按时间排序，提供全量消息计数；历史/显式上下文保留
24,576 字符，最终组装上限 131,072 字符。问题/配置角色有独立 16,384 字符边界。
附件沿用每文件 50 KiB、8 个 / 100 KiB 总量，XML 转义后再次校验组装边界。
来源大小采用实际保留文本的 UTF-8 字节，区分 redacted、truncated 和选中/总条数；
这些不是模型 token 数或真实模型质量承诺。

通用脱敏覆盖完整/未闭合私钥、JSON password、短 Bearer/Basic 以及常见 cloud-key
格式。已有 application-local Host Vault 提供 AI Provider/proxy 的已知值，精确匹配
后再做模式脱敏，应用于附件名/预览、系统角色、问题和上下文；不会扩大为读取
所有 SSH 凭据。最多 32 个 distinct references、每次准备四个并发 Vault 读取、
32 个准备操作；没有 secret cache。读取失败、准备中配置变化或所属取消时不发布
预览。close 中止所属读取并等待 cleanup；File Grant 始终在 finally 撤销。

五分钟 review receipt 使用仅在当前 Service 内存中的 HMAC key，绑定实际安全正文、
model/provider 身份与版本、历史/附件选择、终端/对话目标和有效期。发送前重新构建
并比较；来源、配置、正文、目标、过期或 Runtime 重启都使旧 receipt 失效。receipt
不进入 URL、日志、DB 或 persistent browser storage，也不代替 Runtime auth 或
Tool Approval。已有 authenticated headless callers 可继续使用可选字段之前的接口。

## 界面与生命周期

Composer 发送先准备预览，再通过“确认并发送”发起模型请求；用户可返回修改问题、
移除附件或不包含最近历史。首次对话名取 Runtime 已脱敏的问题/附件信息，不把原始
secret 写入名称。终端“使用 AI 解释”只把 Runtime 已脱敏选区放入待发送界面；
生成、复制、插入和执行审批仍是独立动作。AI 目标采用实际 active terminal，保留
现有 Inspector。切换、新建或删除当前对话清理所属附件，不复用未确认旧草稿。

预览 hook 同步锁定单次准备/发送，拥有 AbortController 与 panel 生命周期，取消、
目标变化和卸载后不接纳迟到结果。已确认发送的迟到 run 返回 ID 后立即取消，避免
丢弃一个仍在运行的 run。实际正文只在组件内存中保留，不写 UI 持久化缓存。
预览通过 Renderer portal 放在页面顶层；小视口侧栏不能覆盖它，标题和操作栏随
滚动保留。新增十八项文案均有四语言草稿，核心目录每语言 2,593 项；人工权利与
译文审校仍 pending。

审批校验新增 tool identity/risk、call/run state、call/approval target/run、canonical
args 和 expiry 一致性。摘要包含 tool、risk、args、target、expiry，修改任何绑定
条件都拒绝执行；取消、过期、重复批准和恢复也遵循已有状态机。
