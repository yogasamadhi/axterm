## 实现与边界

先固定 `PERFORMANCE_BUDGETS.md` 的 1/4/8 个终端负载、512 KiB 待消费上限、
30s/1 MiB/s 吞吐与 1,500ms 交互预算，再保存无消费协议的生产 Electron 测量。
原有 socket `bufferedAmount` 不能证明 xterm parser 待消费队列有界，故先记录
[ADR-024](../../../adr/ADR-024-terminal-output-consumption-window.md)，再实现协议。

- Client 在现有鉴权/来源验证之外请求非敏感 `terminal-flow.v1` 子协议。Runtime
  为每个 attachment 分配新的 stream UUID，`ready` 使用共享 Zod schema，累计
  消费确认必须绑定当前活跃 socket、不能倒退或超过其已发送量。旧 headless/raw
  客户端保留原有传输语义，不添加 Electron business IPC。
- 协商后的 Binary WS frame 最大 64 KiB，256 KiB 高水位、64 KiB 低水位，
  512 KiB 硬上限；另以 4,096/8,192 帧限制小帧 checkpoint 数量。超限显式
  报错并关闭所属 attachment，不静默丢弃，也不增加额外输出队列。
- Renderer 在解码前检查 raw byte/frame 边界，以 xterm 公共 write callback 计量
  已解析字节；确认按 32 KiB 批量发送，不足批量在所属 25ms timer 内刷新。暂停
  parser 时不确认未消费字节。计数和消费延迟仅含数字，终端文本不进入 React、
  Zustand、日志或 persistent browser storage。
- Runtime 的 replay cursor 只在原始 source chunk 全部解析后推进；拆帧的部分
  ACK 不越过 chunk。保留 128 KiB replay 与明确 truncation 语义，不能保证超出
  留存范围的完整终端历史。不同 viewer、替换 socket 和 generation 不共享信用。
- Output/transport/recording 各自持有背压；只有全部释放才恢复 source。日志 drain、
  stop 与 error 均走统一判断。关闭移除 socket listeners、清除 timer/window/checkpoint，
  迟到的 parser callback 和旧 socket event 不操作新会话。
