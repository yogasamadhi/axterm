The new `AXTERM_SOURCE_FILE_REVIEW_LEDGER.json` is a separate, generated
per-file handoff for the **prepared current source snapshot**, not a statement
that the older Git author list owns those bytes. `bun run source:review:generate`
rebuilds its exact path/size/SHA-256 scope and preserves only review fields
whose path and hash remain unchanged; new or changed files return to `pending`.
The ordinary `bun run check` now rejects a stale scope, while
`bun run source:review:reviewed-check` is a separate final-public prerequisite
that rejects any pending or incomplete review. Neither command can establish
the truth of a human-entered rights conclusion, so IR-02 remains in progress.

For reviewer assignment, `bun run source:review:worklist` first checks the
same exact prepared-snapshot scope and then prints every pending path with its
byte count and SHA-256, grouped as assets/legal text, tests/fixtures, product
implementation, build/audit tooling, or documentation/other source. A reviewed
file is omitted from the pending worklist, but only a valid, non-future review
date and the required evidence fields may mark it reviewed. These groups are
work routing, not inferred authorship, license, distribution permission or
legal acceptance. Any source edit changes its hash and returns that file to
pending when the ledger is regenerated.
