## 5. 每轮更新和停止规则

1. 按第 2 节**连续完成当前可执行批次**，先核已有证据，再补真实缺口并验证；不为一个通过的细格人为停工。客观阻塞记录原因、已有证据和解除条件，立刻转下一项可执行工作。新缺陷归现有 W，不无声扩充 46 项；确须新增时先写编号、负责人、依赖和新分母。
2. STATUS 记录编号/格、通过/失败/未运行、测试命令、源码和适用包哈希、证据链接、剩余条件、下一格。本表只在达到“完成”条件后勾选。每轮公开 W 关闭增量、IR Accepted 增量、M1 格增量；0 就写 0。
3. 代码变更运行对应测试，结束前运行 bun run check；最终冻结候选再做 SBOM、法律文本、About、升级和下载字节核对。失败要修代码，不删除测试、不放松架构门禁。
4. ADR-021 已取消公开迁移期，不再有 M2/M3 计时。新仓库和旧仓库删除仍不得根据内部构建、无签名 Mac 包或“已经做了几天”提前宣告完成；先满足来源、包、平台与发行门禁。
